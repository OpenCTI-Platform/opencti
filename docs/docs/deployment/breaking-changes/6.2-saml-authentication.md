# Change to SAML authentication default parameters

!!! info ""

    * **Changed in**: `OpenCTI 6.2`

## Description of changes

Upgrading `passport-saml` library introduced a breaking change with respect to the default SAML parameters regarding signing responses and assertions.

When `want_assertions_signed` and `want_authn_response_signed` SAML parameter are not present in OpenCTI configuration,
the default is now set to `true` by `passport-saml` library when previously it was `false` by default.

## Migrate guide

If SAML login fails after the upgrade, your identity provider (IdP) probably does not sign both the SAML response and the assertions. Set the two parameters explicitly in the configuration of the SAML provider:

| Configuration file key                                   | Environment variable                                        | When `true`                                     |
|:---------------------------------------------------------|:------------------------------------------------------------|:------------------------------------------------|
| `providers:<provider>:config:want_assertions_signed`     | `PROVIDERS__<PROVIDER>__CONFIG__WANT_ASSERTIONS_SIGNED`     | The assertion must carry a valid signature.     |
| `providers:<provider>:config:want_authn_response_signed` | `PROVIDERS__<PROVIDER>__CONFIG__WANT_AUTHN_RESPONSE_SIGNED` | The SAML response must carry a valid signature. |

`<provider>` is the key of the SAML provider in the `providers` section of the configuration, for example `saml`. Set to `false` only the parameter that your IdP cannot satisfy:

- If your IdP signs the assertions but not the response, set `want_authn_response_signed` to `false`.
- If your IdP signs the response but not the assertions, set `want_assertions_signed` to `false`.

For example, for an IdP that signs the assertions but not the response:

```yaml
- PROVIDERS__SAML__CONFIG__WANT_AUTHN_RESPONSE_SIGNED=false
- PROVIDERS__SAML__CONFIG__WANT_ASSERTIONS_SIGNED=true
```

!!! warning "Security impact"

    These parameters decide which parts of the SAML response OpenCTI checks against the IdP certificate (`cert`). Setting one to `false` weakens the check. With both set to `false`, OpenCTI still rejects a response unless the response or its assertion carries a valid signature, but it no longer requires both. Prefer configuring your IdP to sign the response and the assertions.

### Since OpenCTI 7.260224.0

SAML providers are configured in the platform, in **Settings > Security > Authentications** (see [Manage authentication strategies via the graphical interface](../../administration/authentication-via-ui.md#saml)), and SSO requires an Enterprise Edition license. At startup, the platform [migrates the SAML providers of the configuration file](7.260224.0-SSO-authentication-migration.md) to the database. After the migration, the configuration file keys above only apply when `app:authentication:force_env` is `true`.

In a migrated provider, the two parameters are the **Want assertion signed** and **Want authn response signed** toggles, in the **Security & Signing** section of the provider form. When a key is absent from the configuration file at migration time, the migration turns the matching toggle off, instead of the `true` default of the library: check both toggles after the migration.
